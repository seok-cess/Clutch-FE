## 디자인 특이성

쿠폰 운영, Redis 재고, 처리 필요 영역은 CLUTCH 운영 화면답다. 반면 차트는 일반적인 일별 물량 그래프이며, 운영상 중요한 실패 감지와 데이터 완전성 판단이 충분히 반영되지 않았다. 자동 탐지기는 0건을 보고했지만 축척과 데이터 의미는 검사하지 않으므로 품질 통과를 뜻하지 않는다.

## 전체 인상

그래프가 계산상 틀린 것은 아니다. 239,262건과 1건을 같은 선형 축에 놓으면 1건이 거의 0처럼 보이는 것이 정상이다. 문제는 정확성보다 표현 선택이다. 현재 그래프는 큰 발급량은 잘 보여주지만 작은 값과 실패 이상징후는 거의 전달하지 못한다.

## 잘된 점

- KPI에서 추이, 처리 필요, 이벤트 현황으로 이어지는 정보 순서가 자연스럽다.
- 실행 화면에는 Y축, 격자, 3px 최소 양수 막대, 날짜별 접근성 라벨이 들어가 기본적인 판독성을 보완했다.
- 골드 성공과 레드 실패 색상은 기존 관리자 UI와 일관된다.

## 우선순위 문제

1. **P1 — 극단적인 값 차이가 작은 값을 사실상 지운다.** 239,262건 기준에서 1건은 3px 표시로만 남아 추세로 읽히지 않는다. 성공량 차트와 실패/저발급 이상 감지 영역을 분리하거나, 날짜 선택 시 정확한 값과 전일 대비를 강조해야 한다.
2. **P1 — 0·0·1의 의미가 불명확하다.** 실제 수요 급감인지 당일 부분 집계인지 데이터 미수집인지 구분되지 않는다. `집계 진행 중 · 15:33 기준` 같은 상태를 차트 안에 표시하고 미집계는 0이 아니라 `—`로 구분해야 한다.
3. **P1 — 실행 화면과 저장소 소스가 다르다.** 실행 DOM에는 Y축·격자·날짜별 aria-label·최소 막대가 있으나 현재 로컬 JSX/CSS에는 없다. 이 상태로 재빌드하면 지금 보이는 개선 사항이 사라질 수 있으므로 배포 번들의 커밋과 브랜치를 먼저 맞춰야 한다.
4. **P2 — 실패 계열의 운영 중요도가 시각적 크기보다 크다.** 실패가 성공량 축에 묻힌다. 이중축보다는 성공량 차트 아래에 실패 건수 또는 실패율을 작은 정렬 차트로 분리하는 편이 안전하다.
